1. What is Machine Learning?

Machine Learning (ML) is teaching computers to learn patterns from data and make predictions — without being explicitly programmed with rules. Instead of a human writing every rule, the machine discovers the rules from examples.

Traditional programming needs rules; ML learns the rules from data + answers.
Analogy: Traditional programming is like giving someone a recipe (the rules). Machine learning is like showing someone 1,000 finished dishes and letting them figure out the recipe themselves.
Real-world examples: spam detection, Netflix recommendations, loan default prediction, house-price prediction, face recognition, fraud detection.

2. Types of Machine Learning

There are three main families, based on what kind of data and feedback the model gets.

The three types of machine learning.

2.1 Supervised Learning (labeled data)

The data comes with the correct answers (labels). The model learns to map input → output. Two sub-types:

  • Classification — predict a category (spam/not-spam, cat/dog, default/no-default).
  • Regression — predict a number (house price, temperature, salary).
Analogy: A student studying with an answer key — every practice question has the correct answer, so patterns are easy to learn.

2.2 Unsupervised Learning (no labels)

The data has no answers. The model finds hidden structure on its own.

  • Clustering — group similar items (customer segmentation).
  • Dimensionality Reduction — compress features (PCA).
Analogy: Sorting a pile of mixed photos into groups by similarity, without being told the categories.

2.3 Reinforcement Learning (rewards)

An agent learns by trial and error, getting rewards for good actions and penalties for bad ones. Powers game AI (AlphaGo), robotics, self-driving.

Analogy: Training a dog — treats for good behavior, "no" for bad. Over time it learns what to do.

4. Data Preprocessing

Raw data is messy. We must prepare it before modeling.

4.1 Handling Missing Values

  • Drop rows/columns (if very few missing, or a column is mostly empty).
  • Impute — fill with mean/median (numeric) or mode (categorical).
  • Flag — add an "is_missing" indicator if the missingness itself carries meaning.

4.2 Encoding Categorical Data (text → numbers)

Models need numbers. Two main ways:

  • Label Encoding — assign each category a number (Low=0, Med=1, High=2). Use for ordinal data where order matters.
  • One-Hot Encoding — a 0/1 column per category. Use for nominal data (no order) so the model doesn't assume a false ranking.

Bring features to a similar range so no single one dominates (vital for distance- and gradient-based models).

5. Overfitting, Underfitting & Bias-Variance

This is one of the most important concepts in all of ML — expect it in every interview.

Underfitting misses the pattern; overfitting chases every point (incl. noise); good fit captures the trend.

Overfitting (high variance)

The model memorizes the training data including noise. Great on training, bad on new data.

Analogy: A student who memorizes past exam answers word-for-word but can't solve a slightly different question.

Underfitting (high bias)

The model is too simple to capture the pattern. Bad on both training and test data.

Analogy: A student who barely studied — fails both practice and real exams.

The Bias-Variance Tradeoff

As you make a model more complex: bias goes down (fits training better) but variance goes up (more sensitive to data). Total error is a U-shape — the sweet spot is the bottom.

Total error = bias² + variance + noise. The best model minimizes the sum (the green U's bottom).
TermMeaningSymptom
BiasError from too-simple assumptionsUnderfitting — bad on train AND test
VarianceError from being too sensitive to training dataOverfitting — great on train, bad on test

How to actually detect which one you have

Compare training error vs test/validation error:

Training errorTest errorDiagnosis
HighHighUnderfitting (high bias) — model too simple
LowHigh (big gap)Overfitting (high variance) — memorized training data
LowLowGood fit — the goal

The mathematical breakdown of a model's expected error is: Total Error = Bias² + Variance + Irreducible Noise. You can't remove the noise (randomness in the data), but you trade off bias and variance by tuning model complexity.

How to fix each

Fix underfitting (reduce bias): use a more complex model, add more/better features, reduce regularization, train longer.

Fix overfitting (reduce variance): more training data · simpler model · regularization (L1/L2) · cross-validation · dropout (NNs) · fewer features · early stopping.

6. Linear Regression

The simplest regression algorithm. It fits the best straight line through the data to predict a number.

y = w₁x₁ + w₂x₂ + ... + b
  y = prediction (e.g., house price)
  w = weights (importance of each feature)
  b = bias/intercept
The best-fit line minimizes the total squared vertical distance (error) to all points.

How does it actually "learn" the best line?

It searches for the weights (w) and bias (b) that make predictions as close as possible to the true values. "Closeness" is measured by the cost function, Mean Squared Error:

MSE = (1/n) × Σ (yᵢ_actual − yᵢ_predicted)²

Why squared? Two reasons: (1) it makes every error positive so a +5 and a −5 error don't cancel out, and (2) it punishes big mistakes far more than small ones — an error of 10 contributes 100, while an error of 2 contributes only 4. This pushes the model to avoid large errors.

Two ways to find the weights

  • Normal Equation — a direct formula w = (XᵀX)⁻¹Xᵀy that solves for the best weights in one shot. Great for small datasets, but the matrix inversion is slow (O(n³)) when you have many features.
  • Gradient Descent — start with random weights and iteratively nudge them downhill on the MSE curve until you reach the minimum (see §15). This scales to millions of features and is what's used in practice for large data.

Worked example

price = 5000·(size_sqft) + 200000·(bedrooms) − 1000·(age_years) + 100000

A 1000 sqft, 2-bedroom, 10-year-old house:
price = 5000·1000 + 200000·2 − 1000·10 + 100000
      = 5,000,000 + 400,000 − 10,000 + 100,000
      = ₹5,490,000

Each weight is directly interpretable: every extra sqft adds ₹5,000, every bedroom adds ₹2,00,000, every year of age subtracts ₹1,000. This transparency is why linear regression is loved in fields that need explainability.

The 5 assumptions (and why they matter)

  1. Linearity — the true relationship is a straight line. If it's curved, a line underfits (fix: polynomial features).
  2. No multicollinearity — features shouldn't be strongly correlated with each other (e.g., "age" and "years since birth"), or the weights become unstable and unreadable.
  3. Homoscedasticity — the spread of errors stays constant across all values (no funnel shape in the residual plot).
  4. Normality of residuals — errors follow a bell curve (matters for confidence intervals).
  5. No autocorrelation — one error doesn't predict the next (often violated in time series).

Pros, cons & when to use

Pros: simple, fast, highly interpretable. Cons: assumes linearity, and a single outlier can drag the whole line toward it (because errors are squared). Use it as your baseline for any regression problem, or when you need to explain exactly how each feature affects the output.

7. Regularization (Ridge & Lasso)

Regularization penalizes large weights to prevent overfitting — it forces the model to stay simpler.

Normal loss:      MSE
Ridge (L2) loss:  MSE + λ · Σ(wᵢ²)      → shrinks weights toward 0
Lasso (L1) loss:  MSE + λ · Σ|wᵢ|        → can make weights exactly 0
TypePenalty shapeEffect
Ridge (L2)Circle (smooth)Shrinks all weights, keeps all features
Lasso (L1)Diamond (corners)Zeros out some weights → auto feature selection
Elastic NetBothCombines L1 + L2

Why does this prevent overfitting?

An overfitting model fits the training noise by making some weights very large. By adding a penalty for the size of the weights, we force the model to balance two goals: fit the data (low MSE) AND keep weights small (low penalty). It can no longer blow up a weight just to chase one noisy point, so it stays simpler and generalizes better.

The λ (lambda) knob

λ = 0      → no penalty → same as plain regression (may overfit)
λ = small  → gentle shrinkage
λ = large  → heavy shrinkage, weights become tiny (may underfit)
λ = ∞      → all weights → 0 → model just predicts the average

λ is a hyperparameter you tune with cross-validation.

Why does Lasso zero-out weights but Ridge doesn't? (the geometry)

Picture the constraint region the penalty creates. Ridge's Σw² forms a smooth circle; Lasso's Σ|w| forms a diamond with sharp corners sitting exactly on the axes. The best solution is where the error contours first touch this region. Because a diamond has corners on the axes, the touch point often lands on an axis — meaning one weight becomes exactly zero. A circle is smooth, so it rarely hits an axis → weights shrink but stay non-zero.

When to use which

  • Ridge (L2) — when you believe most features matter somewhat, and especially when features are correlated (it splits weight between them).
  • Lasso (L1) — when you have many features and suspect most are irrelevant; it will pick the important ones and discard the rest (automatic feature selection).
  • Elastic Net — when you have many features AND some are correlated (best of both).
Analogy: Packing a suitcase with a weight limit. Ridge says "pack everything, but lighter." Lasso says "only pack the essentials" — it removes items entirely.
Key point: Lasso (L1) does automatic feature selection (drops useless features to zero). Ridge (L2) only shrinks them. λ controls strength — bigger λ = simpler model.

8. Logistic Regression (+ the sigmoid)

Despite the name, it's for classification. It outputs a probability (0 to 1) using the sigmoid function, then applies a threshold (usually 0.5) to decide the class.

The sigmoid squashes any number into a 0–1 probability. Above 0.5 → class 1, below → class 0.

Step by step

  1. Compute a linear score just like linear regression: z = w₁x₁ + w₂x₂ + ... + b (this can be any number from −∞ to +∞).
  2. Squash it into a probability with the sigmoid: σ(z) = 1 / (1 + e⁻ᶻ) → always between 0 and 1.
  3. Apply a threshold: if σ(z) ≥ 0.5 → class 1, else class 0.
z = -∞ → σ = 0.00   (definitely class 0)
z = -2 → σ = 0.12
z =  0 → σ = 0.50   (totally unsure, 50-50)
z = +2 → σ = 0.88
z = +∞ → σ = 1.00   (definitely class 1)

So σ(z)=0.88 literally means "88% probability this is class 1."

The threshold is adjustable

0.5 is the default, but you can move it. In cancer screening you might use 0.3 — catch more potential cancers (higher recall) at the cost of more false alarms. In lending you tune the threshold based on the business cost of a wrong decision.

Why Log Loss and not MSE?

Log Loss (Binary Cross-Entropy): −(1/n) Σ [y·log(ŷ) + (1−y)·log(1−ŷ)]

Two reasons MSE is a bad fit here: (1) MSE combined with the sigmoid produces a non-convex loss surface full of local minima where gradient descent gets stuck; log loss is convex (one global minimum). (2) Log loss heavily punishes confident wrong answers — if the model says "99% spam" but it's not spam, the loss is enormous, giving a strong correction signal.

Multi-class version

For more than 2 classes, use Softmax (multinomial logistic regression), which outputs a probability for each class that all sum to 1 — e.g. [0.7, 0.2, 0.1] → predict class 0.

Pros, cons & use

Pros: fast, outputs real probabilities, highly interpretable. Cons: assumes a linear decision boundary (struggles with complex non-linear patterns), sensitive to outliers. Very popular in credit scoring because regulators want to see exactly how each factor influenced the decision.

9. K-Nearest Neighbors (KNN)

To classify a new point, look at its K closest neighbors and take a majority vote.

With K=3, the new point looks at its 3 nearest neighbors and takes the majority class.
Analogy: "You are the average of the people closest to you." If most nearby points are pink, the new point is likely pink.

How "distance" is measured

  • Euclidean — straight-line distance √[(x₁−y₁)² + (x₂−y₂)² + ...]. The default.
  • Manhattan — sum of absolute differences |x₁−y₁| + |x₂−y₂| + .... Often better in high dimensions.

Choosing K — the key decision

K = 1      → classify by the single nearest point
             → super flexible → OVERFITS (noise-sensitive)
K = large  → averages over many points
             → over-smooths → UNDERFITS
K = √n     → common rule-of-thumb starting point

Tune K with cross-validation, and use an odd K for binary problems to avoid tie votes.

Two critical gotchas

  • Must scale features! If "salary" ranges 0–1,000,000 and "age" ranges 0–100, salary completely dominates the distance. Standardize first so features contribute fairly.
  • Curse of dimensionality: with many features, all points become roughly equidistant and "nearest" loses meaning. KNN degrades badly — reduce dimensions (PCA) first.

Lazy learner: KNN does no training — it just stores the data. All the work happens at prediction time (computing distance to every point), which makes prediction slow on large datasets.

10. Support Vector Machine (SVM)

SVM finds the boundary (hyperplane) that separates classes with the maximum margin — the widest possible gap.

SVM picks the boundary with the widest "street." The closest points (support vectors) define the margin.
Analogy: Drawing the widest possible street between two neighborhoods so they're separated as clearly as possible.

Why maximize the margin?

A wide margin means the boundary is as far as possible from both classes, so it generalizes better to new points. The few points that sit right on the edge of the margin are called support vectors — they're the only points that actually define the boundary. Move any other point and nothing changes; move a support vector and the boundary shifts.

The kernel trick (for non-linear data)

When classes can't be separated by a straight line, SVM maps the data into a higher dimension where it becomes separable, then draws a flat boundary there (which looks curved back in the original space). The "trick" is that it never actually computes those high-dimensional coordinates — a kernel function computes the needed dot products directly, saving huge computation. The RBF kernel effectively maps to infinite dimensions.

The C parameter (bias-variance dial)

High C → punish every misclassification → narrow margin,
          fits training tightly → risk of OVERFITTING
Low C  → tolerate some mistakes → wider margin,
          better generalization → risk of UNDERFITTING

Pros: works well in high dimensions, effective with clear margins. Cons: slow on large datasets, needs scaling, and picking the right kernel/C requires tuning.

11. Decision Trees

A flowchart of yes/no questions that splits the data until reaching a decision.

A decision tree splits on the questions that best separate the classes.

How does it choose which question to ask?

At each node it tries every feature and every threshold, and picks the split that best separates the classes — i.e., makes the resulting groups as "pure" as possible (ideally all one class). Purity is measured two ways:

  • Gini impurity = 1 − Σ(pᵢ²). A pure node (all one class) = 0; a 50-50 mix = 0.5 (worst for binary). Lower is better.
  • Entropy / Information Gain = −Σ(pᵢ·log₂ pᵢ). Pure node = 0, 50-50 = 1 (max disorder). The tree picks the split with the biggest information gain (drop in entropy).

Gini and entropy give nearly identical trees; Gini is faster (no logarithm), so it's the common default.

Trees for regression

Same structure, but leaves predict the average of their samples, and splits are chosen to minimize variance in the child nodes instead of Gini.

Why they overfit & how to control it

Left unchecked, a tree grows until every leaf is perfectly pure — meaning it memorizes the training data including noise. Control it with pruning:

  • max_depth — limit how deep it grows
  • min_samples_split / min_samples_leaf — require a minimum number of samples to keep splitting

Pros: highly interpretable (you can read the exact decisions), no scaling needed, handles non-linear patterns. Con: high variance — a small change in data can produce a completely different tree. That instability is exactly what ensembles (next) fix.

12. Random Forest & Boosting (Ensembles)

Combining many models beats a single one — "wisdom of the crowd." Two main strategies:

Bagging builds trees independently and averages them; boosting builds them sequentially, each fixing prior errors.
MethodHowReducesExample
BaggingParallel trees on random subsets, then vote/averageVarianceRandom Forest
BoostingSequential trees, each fixing prior errorsBiasXGBoost, AdaBoost

The core requirement: diversity

Combining models only helps if they make different errors — if all models make the same mistake, averaging them changes nothing. Both strategies engineer diversity in different ways.

Random Forest in detail

Random Forest = many decision trees + two sources of randomness:

  1. Bootstrap sampling — each tree trains on a random sample of rows (drawn with replacement), so each sees slightly different data.
  2. Random feature subsets — at each split, a tree only considers a random subset of features (√n features for classification). Without this, one strong feature would dominate the first split of every tree, making them all similar.

Individual trees overfit in different directions; averaging their votes cancels out the noise → much lower variance. Bonus: the ~37% of rows each tree didn't see ("out-of-bag") act as a free validation set, and you get feature importance for free.

Boosting in detail

Boosting builds trees sequentially. It starts with a simple model, sees which samples it got wrong, and trains the next tree to focus on those hard cases. Gradient Boosting does this by fitting each new tree to the residual errors of the current ensemble, adding it with a small learning rate so it corrects gradually.

XGBoost is the optimized champion for tabular data: it adds built-in L1/L2 regularization, smart pruning, parallelization, and native missing-value handling. Powerful, but has many hyperparameters to tune.

Bagging vs Boosting summary:
  • Bagging (Random Forest): parallel, independent trees → reduces variance. Hard to overfit. Fast.
  • Boosting (XGBoost): sequential, error-correcting trees → reduces bias. Usually more accurate, but slower and can overfit if over-trained.

13. Clustering & PCA (Unsupervised)

13.1 K-Means Clustering

Groups data into K clusters: pick K centers → assign each point to nearest center → move centers to the mean of their points → repeat until stable.

K-Means groups points around K centroids. Choose K with the "Elbow Method."

K-Means step by step

  1. Pick K and place K centroids randomly.
  2. Assign each point to its nearest centroid.
  3. Move each centroid to the average position of its assigned points.
  4. Repeat steps 2–3 until centroids stop moving (converged).

Choosing K — the Elbow Method: run K-Means for K=1,2,3… and plot the within-cluster error (WCSS). It drops steeply then flattens; the "elbow" bend is a good K. The Silhouette Score (how well-separated clusters are, from −1 to +1) is another way to pick K.

Limitations: must pick K upfront, assumes round equal-sized clusters, sensitive to initialization (fixed by K-Means++) and outliers.

13.2 PCA (Dimensionality Reduction)

PCA compresses many features into fewer while keeping most of the information (variance). It finds new axes (principal components) pointing in the directions of maximum variance, then projects the data onto the top few.

Analogy: Summarizing a 3D object by its most informative 2D shadow — you lose a little detail but keep the essence.

Why use it: speed up training, fight the curse of dimensionality, remove correlated features, and visualize high-dimensional data in 2D/3D. Limitation: the new components are combinations of original features, so they're hard to interpret; it also assumes linear relationships.

Other clustering methods

  • Hierarchical — repeatedly merges the closest clusters into a tree (dendrogram); no need to pre-set K, and you can "cut" the tree at any level. Slow, best for small data.
  • DBSCAN — density-based: groups points packed closely together and labels lonely points as noise/outliers. Great for irregular shapes and when you don't know K, but struggles with clusters of very different densities.

14.2 The Confusion Matrix (foundation of classification metrics)

TP/TN = correct. FP = false alarm (Type I error). FN = missed detection (Type II error).
MetricFormulaUse when
Accuracy(TP+TN)/allBalanced classes (misleading if imbalanced)
PrecisionTP/(TP+FP)False positives are costly
RecallTP/(TP+FN)False negatives are costly (fraud, disease)
F12·P·R/(P+R)Imbalanced data; need balance
Precision vs Recall (fishing): Precision = of the fish you caught, how many were the target? Recall = of all target fish in the lake, how many did you catch?

Worked example — why accuracy lies

Fraud dataset: 1000 transactions, only 20 are fraud (2%).
A lazy model predicts "not fraud" for EVERYTHING.
  Accuracy = 980/1000 = 98%  ← looks amazing!
  But: Recall = 0/20 = 0%     ← it caught ZERO frauds. Useless.

This is why accuracy is misleading on imbalanced data. Precision and recall reveal the truth.

The precision-recall tradeoff

Lowering the decision threshold catches more positives (↑ recall) but also raises false alarms (↓ precision), and vice-versa. You choose based on which error is costlier:

  • False negative worse (missing a fraud, a disease) → favor recall.
  • False positive worse (blocking a legit customer, spam-flagging a real email) → favor precision.
  • Need balance → use F1 (harmonic mean — punishes if either is low).

Type I vs Type II errors

Type I = False Positive ("false alarm" — flagging a healthy person as sick). Type II = False Negative ("missed detection" — telling a sick person they're healthy). In most safety-critical settings, Type II is worse.

14.3 The ROC Curve & AUC

ROC plots TPR vs FPR across thresholds. AUC (area under it) = ranking quality. 1.0 = perfect, 0.5 = random guessing.
Lending example: For rare loan defaults, accuracy is useless (predict "no default" for all = 95% accurate, catches zero). Use recall (catch defaulters), precision (don't reject good customers), and AUC.

15. Gradient Descent (how models learn)

Gradient Descent adjusts the model's weights step by step to minimize the loss. It computes the slope (gradient) and steps downhill.

Gradient descent rolls "downhill" on the loss curve toward the minimum, one step at a time.
Analogy: Blindfolded on a hill, you feel the slope and step downhill repeatedly until you reach the bottom (lowest loss).

The update rule

new_weight = old_weight − (learning_rate × gradient)

The gradient is the slope of the loss with respect to a weight — it points in the direction that increases loss, so we step the opposite way (hence the minus sign). We repeat this for every weight, over and over, until the loss stops decreasing.

The learning rate is the most important setting

Too big  → overshoots the minimum, bounces around, may diverge
Too small → takes tiny steps, painfully slow, may get stuck
Just right → smooth, efficient descent to the minimum

Three flavors (how much data per step)

TypeData per updateTradeoff
Batch GDALL dataAccurate, stable, but slow
Stochastic (SGD)1 sampleFast, but noisy/zig-zags
Mini-batchSmall batch (32–256)Best of both — the standard

Terms: an epoch = one full pass through all the data; an iteration = one weight update (one batch).

16. Interview Q&A

Q: Supervised vs unsupervised?
Supervised uses labeled data to predict outputs; unsupervised finds patterns in unlabeled data.
Q: Overfitting and how to fix it?
Model memorizes training data and fails on new data. Fix with more data, simpler models, regularization, cross-validation, dropout, fewer features.
Q: Bias-variance tradeoff?
Bias = too-simple (underfit). Variance = too-complex (overfit). Balance both to minimize total error.
Q: Precision vs recall?
Precision matters when false positives are costly; recall when false negatives are costly (fraud, disease).
Q: Ridge vs Lasso?
Ridge (L2) shrinks weights toward zero; Lasso (L1) can zero them out → automatic feature selection.
Q: Random Forest vs Gradient Boosting?
RF = parallel trees averaged (bagging, reduces variance). GB = sequential trees fixing errors (reduces bias, usually more accurate but slower).
Q: Why does logistic regression use log loss, not MSE?
MSE + sigmoid is non-convex (gradient descent gets stuck). Log loss is convex and penalizes confident wrong answers.
Q: How to handle imbalanced data?
Resampling (SMOTE), class weights, right metrics (F1/AUC/recall not accuracy), threshold tuning.
Q: When do you NOT need feature scaling?
Tree-based models (Decision Tree, Random Forest, XGBoost) — they split on thresholds, not distances.
Q: What is cross-validation?
Split data into K folds, test on each in turn, average — a more reliable performance estimate than one split.

Focus on bias-variance, the tree family (Tree → Random Forest → XGBoost), the sigmoid/logistic idea, and classification metrics — these dominate interviews. 🚀
